## 2. Centralized Logging (CloudWatch Logs)

### 2.1 Backend Application Log Stream
* **Log Group**: `/ecs/ecommerce-<environment>-backend`
* **Driver**: `awslogs` with streaming batch uploads from ECS Fargate.
* **Retention**: Configured via Terraform (14 days for staging, 30 days for production) to balance compliance with cost efficiency.

### 2.2 Error Metric Filter
A custom CloudWatch Metric Filter scans incoming log streams in real-time for application anomalies:
* **Filter Pattern**: `?ERROR ?Error ?Exception ?CRITICAL ?500`
* **Metric Name**: `BackendErrorCount`
* **Metric Namespace**: `ecommerce/<environment>/Application`
* **Purpose**: Tracks unhandled application exceptions and server errors without parsing raw log volumes manually.

## 3. CloudWatch Metric Alarms (Proactive Alerting)

The following automated alarms monitor infrastructure and service health, routing alerts to an Amazon SNS Topic (`ecommerce-<environment>-alerts`):

| Alarm Name | Metric Monitored | Threshold | Evaluation Window | Action |
| :--- | :--- | :--- | :--- | :--- |
| **ECS High CPU** | `AWS/ECS CPUUtilization` | $\ge 80\%$ | 2 consecutive 2-min periods | SNS Alert |
| **ECS High Memory** | `AWS/ECS MemoryUtilization` | $\ge 80\%$ | 2 consecutive 2-min periods | SNS Alert |
| **ALB 5XX Errors** | `AWS/ApplicationELB HTTPCode_Target_5XX_Count` | $> 5$ errors | 1 evaluation 5-min period | SNS Alert |
| **ALB High Latency** | `AWS/ApplicationELB TargetResponseTime` | $> 2.0$ seconds | 2 consecutive 2-min periods | SNS Alert |
| **RDS High CPU** | `AWS/RDS CPUUtilization` | $\ge 80\%$ | 2 consecutive 5-min periods | SNS Alert |
| **RDS Low Storage** | `AWS/RDS FreeStorageSpace` | $< 5$ GB | 1 evaluation 5-min period | SNS Alert |

## 4. Provisioned CloudWatch Dashboards

Two dedicated operational dashboards are defined and managed as code in Terraform:

### Dashboard 1: `ecommerce-<environment>-infrastructure-dashboard`
Designed for SREs and DevOps engineers to monitor core cloud infrastructure components:
1. **ALB Request Volume & Latency**: Dual-axis graph correlating total request counts with target response times.
2. **HTTP Response Code Breakdown**: Real-time distribution of 2XX (healthy), 4XX (client errors), and 5XX (server errors).
3. **ECS Cluster Compute Utilization**: Side-by-side time series of CPU and Memory consumption.
4. **RDS PostgreSQL Health**: Multi-metric widget displaying DB CPU utilization, active database connections, and freeable RAM.

### Dashboard 2: `ecommerce-<environment>-application-dashboard`
Designed for application developers and product teams to assess end-to-end service availability:
1. **ECS Service Task Count**: Tracks Running Task Count vs. Desired Task Count to verify auto-scaling behavior and healthy task lifecycle.
2. **Backend Application Errors**: Real-time spike detection for unhandled exceptions generated by the log metric filter.
3. **CloudFront Global Delivery**: Total global requests and downloaded bytes served from edge locations.
4. **CloudFront Global Error Rates**: Edge 4xx and 5xx percentages across all global regions.
